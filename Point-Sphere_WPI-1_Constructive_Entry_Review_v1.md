## 2. Scope and ontology: incomplete weak-simplicity condition

The packet's prose says that weak simplicity excludes partitive composition. Its displayed definition is only:

\[
\mathsf{WeakSimple}(G)
\iff
\neg\exists x,y[
\mathsf{Part}(x,G)
\land
\mathsf{Part}(y,G)
\land
x\neq y
\land
\mathsf{Separable}(x,y)
].
\tag{WS-Given}
\]

This does not exclude distinct but inseparable partitive constituents. It is compatible with:

\[
\mathsf{Part}(x,G)
\land
\mathsf{Part}(y,G)
\land
x\neq y
\land
\neg\mathsf{Separable}(x,y).
\tag{Inseparable-Parts}
\]

Nor does \((\mathrm{WS\text{-}Given})\) state how \(\mathsf{BPart}\), \(\mathsf{FPart}\), partitive composition, formal distinction, and immanence are related. The packet separately stipulates that its six formalities are not parts, but it does not give a single typed no-composition condition covering the ontology it claims.

Thus the documented weak-simplicity core is not yet determinate enough to test whether the formalities satisfy its own nonpartitivity condition:

\[
\boxed{
\mathsf{WeakSimplicityCore}
\text{ is underdefined at entry scope.}
}
\tag{R1}
\]

This is not an argument that formalities are parts. It is an entry-level request for a fixed criterion deciding that question.

## 4. Truth/error rule: unresolved actual-anchor and key conditions

The packet appropriately avoids the direct rule:

\[
\mathsf{Claims}(s,\lambda)
\to
\mathsf{Fit}(s,\lambda).
\]

But its frozen fit clause is:

\[
\mathsf{Fit}(s,\lambda)
\iff
\mathsf{Claims}(s,\lambda)
\land
\exists a,p[
\mathsf{Anchor}(s,a)
\land
\mathsf{CodeOf}(a,p)
\land
\lambda\approx_{\rm WPI}\mathsf{ObsProj}(p)
].
\tag{Fit-Given}
\]

There is no condition that the anchor articulation be actual or that it profile the entity hosting the actual presentation:

\[
\mathsf{Anchor}(s,a)
\not\Rightarrow
\mathsf{ActArt}(a),
\tag{Anchor-Actuality-Gap}
\]

\[
\mathsf{Anchor}(s,a)
\land
\mathsf{PresOf}(s,e)
\not\Rightarrow
\mathsf{Profiles}(a,e).
\tag{Anchor-Host-Gap}
\]

The primitive uniqueness clauses also do not declare key injectivity:

\[
\mathsf{ArtKey}(a,k)
\land
\mathsf{ArtKey}(a',k)
\not\Rightarrow
 a=a'.
\tag{Key-Gap}
\]

Therefore an actual presentation may be classified as fitting by anchoring to an unactualized or host-unrelated articulation. This blocks the intended actual-fit test.

Further, \(\mathsf{Fit}\) includes \(\mathsf{Claims}\) as a conjunct. That can be a legitimate correctness architecture if named as claim-relative fit, but it does not define a claim-independent matching relation. The packet must decide this before battery execution; it cannot alternate between:

\[
\text{fit as semantic match}
\qquad\text{and}\qquad
\text{fit as claim-relative verdict}.
\tag{Fit-Scope}
\]

Accordingly:

\[
\boxed{
\mathsf{TruthErrorRule}
\text{ is not yet complete enough for Z2.}
}
\tag{R3}
\]

\qquad

\tag{Norm-Gaps}

The fixed value order by itself does not determine the action successor relation, the feasible action set, the veto test, or the lexicographic comparison. Z3.2 therefore cannot be run without new operational additions.

The modular lattice update \((\mathrm{PHYS})\) is an exact toy recurrence. But the packet does not define:

\mathsf{PhysField}_{V_5,\mathbb Z_{101}}(p),
\qquad
\mathsf{Satisfies}_{\rm PHYS}(p),
\tag{Phys-Gaps}
\]

nor the fixed continuum/coarse-graining map, conservation diagnostics, Lorentz-type recovery target, or empirical discriminator required by Z3.4.

This does not show that the toy update is incoherent. It means physical adequacy cannot yet be tested under the frozen packet.
